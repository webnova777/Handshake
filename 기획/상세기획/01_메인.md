## 글자 수 상한 계산 기준

Pretendard 실측(2026.10.22, 100px 로 그려 잼) : 한 글자 평균 폭 — 제목(800) **0.86em** · 카드 제목(700) **0.84em** · 본문(400) **0.80em** (띄어쓰기 포함 평균).
여유 7px 을 뺀 폭으로 계산(CLAUDE.md 2-A). 모바일 폭은 375px 기준(콘텐츠 335px), 데스크톱은 콘텐츠 1120px(1200 − 좌우 40).
한글은 **단어 단위로 줄이 바뀌므로**(keep-all) 실제 줄 수는 상한보다 늘 수 있다 — 최종 확인은 ⑧ 상세 와이어 실측.

## M-01. 히어로 + 일하는 과정 모션그래픽

**목적** : 회사 정체를 첫 화면 한 문장으로 밝히고, 스크롤하면 **계약 → 사전작업 → 납품 → 사후관리**를 한 업체가 끝까지 맡는 흐름으로 보여준다.

### 1) 첫 화면(히어로)

**구성 요소(위→아래)** : 라벨 → 헤드라인(h1) → 리드 → 버튼 2개 [상담 신청](주) · [일하는 과정 보기 ↓](보조)

**데스크톱**
- 섹션 높이 = **첫 화면 높이**(헤더 포함). 최소 640px. 화면 높이는 처음 한 번 재서 고정하고 **폭이 바뀔 때만** 다시 잰다(CLAUDE.md 2번)
- 비주얼이 섹션 전체를 덮고, 글 묶음은 **1~7열(최대 720px)·왼쪽 정렬·세로 가운데**
- 버튼 2개는 **가로 나란히**, 간격 12px. 글 묶음 아래 32px
- 헤더는 이 섹션 위에 **투명으로 겹친다**(3-2, 1-5)
- 글은 비주얼 위에 바로 놓이므로 **대비 4.5:1(큰 글 3:1)** 을 실측으로 맞춘다 — 비주얼이 정해지면 디자인에서 어둡게 깔거나 글 뒤만 눌러 준다(CLAUDE.md 8번)

**모바일(≤768px)**
- 높이는 **내용 기준**(화면 높이에 걸지 않음). 위 여백은 헤더(60px) 아래 48px, 아래 여백 40px
- **글 → 비주얼 순서로 분리**한다 — 글 묶음 아래에 비주얼 16:9 블록. 좁은 화면에서 글을 비주얼 위에 얹으면 대비를 맞추기 어렵다
- 버튼 2개는 **세로로 쌓고 각각 전체 폭**, 주 버튼이 위, 간격 12px

**동작**
- 로드와 동시에 등장 — 라벨 → h1 → 리드 → 버튼 순으로 **겹쳐서** 떠오름(간격 0.12초, 이동 16px). **스크롤 감지·스크립트 없이 CSS 로**(1-1)
- 히어로 진입 시간 값은 `프로젝트사양.md` 6번 [대기] — 정해질 때까지 본문 진입값(0.8초)을 쓴다
- [일하는 과정 보기 ↓] : 장면 구간 시작으로 부드럽게 스크롤(3-A — CSS `scroll-behavior` 금지, JS 로 시도 후 확인)

**문구 자리와 글자 수 상한**

| 자리 | 상한 | 근거 | 지금 [가안] (글자 수) |
|---|---|---|---|
| 라벨 | 1줄 · 20자 | 모바일 14px | 병원 통신·보안·가전 솔루션 (15) |
| h1 | **2줄 · 줄당 14자 · 합계 22자** | 데스크톱 56px·720px → 줄당 14자 / 모바일 32px → 줄당 11자 | 편리하게 납품하고 / 신속하게 지킵니다 (9 / 9) |
| 리드 | 모바일 3줄 · 70자 | 모바일 16px → 줄당 25자 | 병원 진료를 지키기 위해, 계약부터 설치, 개원 후 A/S까지 핸드쉐이크가 책임집니다. (45) |
| 버튼 | 8자 | — | 상담 신청 / 일하는 과정 보기 ↓ |

- h1 의 데스크톱 줄바꿈은 지정 위치(PC 전용 줄바꿈 `brk-pc`, 2번)에서만 — 모바일은 자연 줄바꿈

### 2) 일하는 과정(스크롤 장면)

**구성 요소** : 섹션 제목(h2) → 장면 4개 [번호 1/4 · 단계 이름 · 설명 1~2줄 · 비주얼] → 단계 표시(점 4개)

**데스크톱 — 고정 무대**
- 섹션 제목은 무대 위(1~8열)
- 무대 : 화면에 **고정**된 채 스크롤로 장면이 바뀐다. 왼쪽 **1~5열 = 글**(번호 → 단계 이름 → 설명 → 단계 표시 점 4개), 오른쪽 **6~12열 = 비주얼 16:9**
- 고정 구간 길이 = 장면 4개 × **고정된 화면 높이**(1)과 같은 값). 장면 1개당 화면 1개 분량 스크롤
- 단계 표시 점 : 현재 장면 강조. **누르면 그 장면 위치로 이동**(키보드로도 — 8번 포커스 표시)

**모바일 — 고정하지 않는다**
- 장면 4개를 **세로로 나열** : 번호·단계 이름·설명 → 아래 비주얼 16:9. 장면 사이 40px, 사이에 얇은 구분선
- 이유 : 모바일 고정 구간은 주소창 높이 변화로 흔들린다(CLAUDE.md 2번). 나열해도 이해되게 설계

**동작**
- 데스크톱 장면 전환 : 글은 0.8초, 비주얼은 1.1초, 앞 장면이 빠지는 동안 다음 장면이 들어온다(**겹치기**, 4번)
- 화면 밖이면 애니메이션 멈춤(3번). 움직임 줄이기 설정 → 고정 없이 모바일처럼 나열
- JS 꺼짐 → 4장면 전부 펼친 상태(1-2 `@media (scripting:none)`)

**문구 자리와 글자 수 상한**

| 자리 | 상한 | 지금 [가안] |
|---|---|---|
| 섹션 제목 h2 | 2줄 · 합계 28자(모바일 줄당 14자) | 계약부터 사후관리까지, 한 업체가 끝까지 (20) |
| 단계 이름 ×4 | 6자 | 계약 · 사전작업 · 납품 · 사후관리 [확정] |
| 단계 설명 ×4 | 2줄 · 60자(데스크톱 5열 폭 453px · 17px → 줄당 32자) | 기획안 M-01 장면표 참고 (현재 30~50자) |

**데이터·자료** : 비주얼 4장(표현 방식 미정 — 캐릭터 / 인포그래픽 / 실사·AI) [대기], 로고 원본 [대기]. 영상이면 외부 CDN(1-3)

**예외** : 장면 비주얼이 늦으면 → 정지 이미지 4장(또는 회색 자리)로 먼저 열고 모션은 나중에 교체할 수 있게 구조를 나눠 둔다

## M-04. 대표 포트폴리오

**목적** : "진료과별로 맞춤 제안이 가능하다"를 실제 사례로 보여준다.

**구현 방식** : **아임웹 갤러리 위젯** [확정] — 코드 위젯이 아니다. 우리 CSS 가 안 걸리므로(1-4) 글꼴·줄바꿈은 전역 CSS 로 맞춘다.
위아래 코드 위젯 섹션과 **좌우 폭·제목 크기·여백을 같게** 맞춘다(1-6)

**구성 요소** : 섹션 제목(h2) → 사례 사진 6건 [사진 + 캡션 2줄] → [포트폴리오 전체 보기] 버튼

**보여줄 건수 : 6건** [확정 제안 — 2026.10.22 상세 기획, 확인 요청]
- 이유 : 3건이면 진료과 다양성이 안 보이고, 9건이면 메인이 길어진다. 6건 = 데스크톱 2행 · 모바일 3행으로 딱 떨어진다
- 고르는 법 : 포트폴리오 페이지(P-01)와 **같은 원본**에서 대표님이 고른 6건 — 원본을 두 벌 두지 않는다(6번). 갤러리 위젯이 "같은 원본 + 건수 지정"을 지원하지 않으면 메인용 갤러리를 따로 두고, **어느 쪽을 고쳐야 하는지** 대표님용 안내를 남긴다 [아임웹 설정 확인]

**데스크톱** : 제목 1~8열. 사진 **3열 × 2행**, 간격 24px, 사진 **4:3**. 캡션은 사진 아래 : 1줄 병원명(굵게) · 2줄 진료과 · 지역. 버튼은 사진 아래 40px, **가운데**
**모바일** : 사진 **2열 × 3행**, 간격 12px, 사진 4:3. 캡션 같은 구성(글자 작게). 버튼 전체 폭

**동작** : 사진 누르면 → 그 사례 상세(포트폴리오 게시판 글). 진료과 탭은 **메인에는 두지 않는다**(포트폴리오 페이지에만) — 메인은 짧게
