## M-01. 히어로 — 일이 진행되는 과정 모션그래픽

> 2026.10.23 구조 변경(사용자 지정) : 히어로와 일하는 과정을 **한 섹션**으로 합친다. **첫 화면 자체가 모션그래픽**이다(카누 첫 섹션 방식).
> 이전안(첫 화면 글 + 아래 고정 무대 2단)은 폐기.

**목적** : 회사 정체를 첫 화면 한 문장으로 밝히고, 같은 화면에서 이어서 **계약 → 사전작업 → 납품 → 사후관리**를 한 업체가 끝까지 맡는 흐름으로 보여준 뒤, 대표 카피로 맺는다.

**단계(6개)** — 모두 같은 화면 안에서 바뀐다

| 단계 | 화면 | 글 위치(데스크톱) |
|---|---|---|
| 0 첫 화면 | 화면 가득 모션그래픽 + 라벨 · h1 · 리드 (**버튼 없음**) | 가운데 정렬(최대 760px) · 세로 가운데 |
| 1 계약 | 장면 1 모션그래픽 + 번호 1/4 · 단계 이름 · 설명 | 가운데 정렬(최대 600px) · 세로 가운데 |
| 2 사전작업 | 장면 2 | 같음 |
| 3 납품 | 장면 3 | 같음 |
| 4 사후관리 | 장면 4 | 같음 |
| 5 대표 카피 | 모션그래픽 없이 기본 배경 + 대표 카피(h1 크기) + 한 줄 | 가운데 정렬 · 세로 가운데 |

→ 대표 카피가 멈춘 채로 **M-02 가 아래에서 덮으며 올라온다**(I-02)

- **글은 모든 단계에서 상자·배경 없이 글자만, 가운데 정렬. 버튼은 두지 않는다**(2026.10.23 사용자 지정)

**데스크톱 — 고정 무대(I-01)**
- 섹션 높이 = **화면 높이**(최소 640px). 헤더는 이 섹션 위에 투명으로 겹친다(3-2, 1-5). 스크롤을 내리면 헤더는 숨는다
- 스크롤 길이 : **한 단계당 화면 0.8개 분량** × 5번 전환 + 덮기 1화면 = 화면 5개 분량 [와이어 임시값 — 흐름 보고 조정]
- 단계 막대 : 화면 아래 40px, **가운데 · 폭 480px**, 4칸(계약·사전작업·납품·사후관리). 지나간 칸은 차오른다. **표시만 한다 — 누르는 버튼이 아니다**. 0단계에도 보이고, 5단계(대표 카피)에서 사라진다
- 글이 모션그래픽 위에 상자 없이 바로 놓이므로 **대비 4.5:1(큰 글 3:1)** 은 모션그래픽을 어둡게 깔아 맞춘다 — 실측(8번). 글 뒤 상자는 쓰지 않는다

**모바일(≤768px) — 데스크톱과 같은 방식**(2026.10.23 사용자 지정)
- 화면에 고정된 채 **위아래 스크롤로** 단계가 바뀐다. 글은 가운데 정렬, 장면 이름은 h2 크기(26px)
- 높이 = **처음 한 번 잰 화면 높이로 얼린다**(최소 520px). 주소창이 접혔다 펴져도 다시 재지 않고, 폭이 바뀔 때만 다시 잰다(2번). `100vh` 를 그대로 쓰지 않는다
- 단계 표시는 하단 고정 바(G-08, 60px) 위 20px, 좌우 20px 여백. 글자 11px
- 상담 버튼은 하단 고정 바(G-08)가 맡는다

**움직임 줄이기 · JS 꺼짐 — 고정하지 않는다**
- 세로 나열 : 0단계 [글 → 모션그래픽] → 장면 1~4 [번호·이름·설명 → 모션그래픽] → 대표 카피. 글은 모두 가운데 정렬

**동작**
- 0단계 첫 등장 : **CSS 로 로드 즉시**(스크롤·스크립트 없이, 1-1) — 라벨 → h1(줄마다) → 리드, 간격 0.12초. 모션그래픽은 크게 시작해 가라앉음(I-09). 히어로 속도 [미정 — 와이어는 0.8초·2.4초 임시]
- 단계 전환 : 글 0.8초 · 모션그래픽 1.1초, 앞 단계가 빠지는 동안 다음이 들어온다(겹치기, 4번). 단계는 스크롤 위치로 정해지고 **되감으면 거꾸로** 돌아간다

- 덮일 때 무대는 6% 작아지고 35% 어두워진다(스크롤에 맞춰)
- 데스크톱 고정 배치는 **JS 가 돌기 전부터 CSS 기본값**으로 둔다(1-1) — JS 가 늦으면 나열 → 고정으로 바뀌며 깜빡인다. JS 꺼짐은 `@media (scripting:none)` 로 나열(1-2)

## M-02. 핵심가치 3가지

**목적** : "맡기면 나에게 무엇이 좋은가"를 세 가지로 답한다 — **시간 절약(턴키) · 비용 절감 · 정확한 가이드**(2026.10.23 사용자 지정). "핵심가치"는 기획 안의 섹션 이름이다 — 화면 제목에 그 말을 쓸지는 ⑦ 에서(회사 소개 A-02 핵심가치 신뢰·성장과 겹치지 않게)
**회사 소개로 넘기는 다리** — [회사 소개 보기 →] 로 /about 에 보낸다

> 2026.10.23 변경(사용자 지정) : 카드 3열 → **전체 화면 이미지 + 스크롤하면 좌→우 슬라이드**. 이전 카드안은 폐기

**구성 요소** : 섹션 제목(h2, 그대로 남음) → 가치 3개 [번호 01/03 · 제목 · 설명 + 전체 화면 이미지] → [회사 소개 보기 →](그대로 남음) → 진행 표시 3칸

**데스크톱 — 화면 고정(I-11)**
- M-01 을 덮으며 올라온 뒤(I-02) 이 섹션이 **화면에 고정**된다. 높이 = 화면 높이(최소 640px)
- 이미지 3장이 화면 전체를 채운다. 스크롤하면 이미지 띠가 **왼쪽에서 오른쪽으로** 밀리며 다음 장이 왼쪽에서 들어온다 — **스크롤에 붙어서** 움직인다(손을 멈추면 중간에 멈춤)
- 글 묶음 : **왼쪽 정렬**, 1~6열(최대 560px), 세로 가운데. 위에서부터 제목(h2) → 40px → 가치 글(번호 · 제목 · 설명) → 40px → 버튼 → 28px → 진행 표시
- 가치 글은 **화면의 절반을 넘긴 장 기준으로 바뀐다** — 나가는 글은 사라지고, 새 글이 왼쪽에서 16px 밀려 들어온다(0.8초)
- 진행 표시 : 3칸 막대(120px), 지금 장 강조. 표시만 한다
- 스크롤 길이 : 한 장당 화면 1개 분량 → 2번 넘김 = 화면 2개 [와이어 임시값]
- 글이 이미지 위에 놓이므로 대비 4.5:1 — 이미지 왼쪽을 어둡게 깔아 맞춘다(실측, 8번)

## M-04. 대표 포트폴리오

**목적** : "진료과별로 맞춤 제안이 가능하다"를 실제 사례로 보여준다.

**구현 방식** : **아임웹 갤러리 위젯** [확정] — 코드 위젯이 아니다. 우리 CSS 가 안 걸리므로(1-4) 글꼴·줄바꿈은 전역 CSS 로 맞춘다.
위아래 코드 위젯 섹션과 **좌우 폭·제목 크기·여백을 같게** 맞춘다(1-6)

**구성 요소** : 섹션 제목(h2) → 사례 사진 6건 [사진 + 캡션 2줄] → [포트폴리오 전체 보기] 버튼

**보여줄 건수 : 6건** [확정 제안 — 2026.10.22 상세 기획, 확인 요청]
- 이유 : 3건이면 진료과 다양성이 안 보이고, 9건이면 메인이 길어진다. 6건 = 데스크톱 2행 · 모바일 3행으로 딱 떨어진다
- 고르는 법 : 포트폴리오 페이지(P-01)와 **같은 원본**에서 대표님이 고른 6건 — 원본을 두 벌 두지 않는다(6번). 갤러리 위젯이 "같은 원본 + 건수 지정"을 지원하지 않으면 메인용 갤러리를 따로 두고, **어느 쪽을 고쳐야 하는지** 대표님용 안내를 남긴다 [아임웹 설정 확인]

**데스크톱** : 제목 1~8열. 사진 **3열 × 2행**, 간격 24px, 사진 **4:3**. 캡션은 사진 아래 : 1줄 병원명(굵게) · 2줄 진료과 · 지역. 버튼은 사진 아래 40px, **가운데**
**모바일** : **3건만**(2026.10.23 사용자 지정) — 위에 **큰 1건(전체 폭)**, 아래 **작은 2건(2열)**, 간격 12px, 사진 4:3. 캡션 같은 구성(글자 작게). 버튼 전체 폭
- 3건 = 데스크톱 6건 중 앞 3건. 갤러리 위젯이 기기별 개수를 못 정하면 전역 CSS 로 4~6번째를 숨긴다(모바일용 위젯을 따로 두지 않는다 — 6번)

**동작**
- 사진 누르면 → 그 사례 상세(포트폴리오 게시판 글). 진료과 탭은 **메인에는 두지 않는다**(포트폴리오 페이지에만) — 메인은 짧게
- **호버(I-12, 2026.10.23 사용자 지정)** : 사진에 마우스를 올리면 사진 전체에 **어두운 오버레이**가 깔리고 가운데 **악수 로고**(흰색, 지름 96px)가 나타난다. 0.24초, 로고는 0.92 → 1 로 살짝 커진다. 키보드 포커스에도 같게(8번)
- 터치 화면은 호버가 없다 — 오버레이 없이 누르면 바로 상세로
- ⚠ **아임웹 갤러리 위젯에는 우리 CSS 가 안 닿는다(1-4)**. 이 호버를 넣으려면 ① 사이트 전역 CSS 로 갤러리 위젯을 잡거나(`:has()` 로 그 섹션 한정) ② 코드 위젯으로 바꾼다. ①은 갤러리 위젯의 장점(대표님이 직접 올림)을 지키고, ②는 사례를 올릴 때마다 코드를 고쳐야 한다 → **①을 기본으로, ⑧ 실측에서 되는지 확인** [구현 확인 필요]
